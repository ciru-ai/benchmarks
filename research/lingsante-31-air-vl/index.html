Method

How we timed it

Download results JSON ↓

One machine, one request at a time. Both engines served the same model on the same M5 Ultra Mac Studio. llama.cpp ran first, followed by Ciru RCS. Every reported request used plain decode with zero draft tokens.

Prefill and decode in one request. For each matched length, both engines read identical uncached input tokens and generated 512 tokens greedily. Rates use each engine’s native timings. Prefill measures input processing. Decode measures generation after the first token.

Sampled workloads. HumanEval and prose used temperature 1.0, top-p 0.95, top-k 20, min-p 0, seed 15035 and a 1,024-token output cap. HumanEval pools generated tokens and decode time across all ten cases. Output lengths can differ. The ten cases measure throughput only.
