Chadrock ROCmFP4 vs Unsloth Upstream Q4/Q6 Comparison

Date: 2026-06-30.

This adds the requested comparison rows against the ROCmFP4 Chadrock builds and Unsloth Q4/Q6. Unsloth rows used upstream llama.cpp, not the ROCmFPX/CHADROCK fork, version 1 (7c082bc). Chadrock ROCmFP4 rows used profile-capable CHADROCK/ROCmFPX runners because upstream llama.cpp cannot load those ROCmFP4 GGUFs.

Harness: isolated llama-server, one slot, /completion streaming API, llama_benchmark.py api, prompt cache disabled, EOS ignored, gen=128, non-wiki 10KB and 20KB deterministic prompts from the prior recipe sweep. Reported context tokens are actual tokenized prompt lengths: about 1977 and 3946.

Memory note: memory columns are normalized to one displayed Peak total RAM GiB value instead of separate VRAM/GTT/system RAM triples.

Takeaways

  • Fastest 4k MTP row in this combined local evidence set is Qwable Chadrock v2 ROCmFP4 at 298.48 PP / 51.26 TG, despite only 4.3355 tensor BPW.
  • The best upstream llama.cpp Unsloth baseline is UD-Q4_K_XL at 263.88 PP / 41.60 TG at 4k MTP. It is larger than Chadrock ROCmFP4 at 5.2409 BPW and still trails Qwable Chadrock v2 in decode.
  • UD-Q6_K_XL is the quality/PPL anchor among the new baselines (6.5296 +/- 0.09339) but is not a speed competitor here: 198.38 PP / 23.76 TG at 4k MTP, 8.28 TG without MTP, and about 23.37 GiB peak GTT.
  • MTP is mandatory for these MTP models if speed matters. At 4k, new-row decode uplifts ranged from 2.51x to 3.60x versus no-MTP.
  • No local PPL evidence was found for the Chadrock ROCmFP4 or Unsloth Q4 rows; the available quality evidence for those rows is coding benchmark output rather than Wikitext PPL.
