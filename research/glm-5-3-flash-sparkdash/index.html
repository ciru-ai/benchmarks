Measuring the first token

Weights stay in memory while each prompt starts cold. SparkDash divides the rendered token count by time to first visible text, adjusted for startup overhead. The latency chart shows the full wait. Ciru recorded 17 samples across seven lengths.

Measuring generation

Requests start together at temperature 0.7. Aggregate throughput counts 399 tokens per stream from the earliest first token to the latest last token. Per-stream speed averages the individual rates. Four-stream results use the median of three trials.

Measurement details & prompt samples

Ciru measured prefill and sampled generation on two Ciru RCS revisions on the same Mac Studio. SparkDash 2.77.0 selected the lower median prefill sample at each size. The calibration was 203.8 ms, capped at half the observed latency. Raw speed includes the full wait to the first visible token. Engine speed uses native prefill time.

Sampled generation used thinking on, top-k 20 and top-p 1. First-token latency is the median across streams. The two single-stream workloads used temperature zero and 400 output tokens.
