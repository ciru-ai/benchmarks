Measuring the first token

Weights stay in memory while each prompt starts cold. SparkDash divides the rendered token count by the time to first streamed text, including reasoning, adjusted for startup overhead. The latency chart shows the full wait. Ciru recorded 17 samples across seven lengths.

Measuring generation

Requests start together at temperature 0.7. Aggregate throughput counts 399 tokens per stream from the earliest first token to the latest last token. Per-stream speed averages the individual rates. Four-stream results use the median of three trials.

Measurement details & prompt samples

SparkDash 2.91.0 selected the lower median prefill rate at each size. The calibration was 188.54 ms, capped at half the observed latency. Raw speed uses the full client wait to first text. Server speed uses the server’s own timings.

Ciru’s sampled generation used thinking on, max effort, temperature 0.7, seeded top-k 20 and top-p 1. First-token latency is the median across streams. The four-stream chart uses the median-throughput trial, including its per-stream speed and latency.
